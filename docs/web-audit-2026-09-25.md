## Fixed during this audit (verified by re-run)

- **Console error** on every page: `/favicon.ico` 404 → added `public/favicon.svg` + `<link rel="icon">` on all 14 entries. Best Practices 96 → 100.
- **Missing preconnect** to `https://cdn.fontshare.com` (fonts came from a second origin the page only discovered after the CSS arrived; est. 300 ms) → added on all pages. `uses-rel-preconnect` now passes.
- **A11y `label-content-name-mismatch`** on `a.brand` (visible "SOKO·MOTO" not inside the aria-label) → label now "SOKO·MOTO home".
- **A11y `aria-required-children`** on the product gallery (`role="tablist"` containing plain buttons) → buttons now `role="tab"` with `aria-selected` kept in sync by both thumb clicks and swatch changes.
- **A11y `color-contrast`** on the PDP: outlined `.pdp__num` (2.3:1) and inactive `.tech__item` (2.49:1) → stroke alpha .28 → .50, item opacity .30 → .56 (≈4.6:1). Product accessibility 91 → 100.

## High priority (3)

### H-1 · Home LCP 5.8 s and TBT > 1 s come from the headline split-text architecture
- **Category:** Performance (LCP, TBT/INP risk)
- **Evidence:** LCP element is `.hero__line-inner`; LCP breakdown = TTFB 15 ms + **element render delay 1.6–5.3 s**: the hero text is invisible until `main.js` (215 kB / 77 kB gz) has downloaded, executed and set 1,144 inline transforms. Main-thread breakdown: Style & Layout **5.0 s**, Other 4.4 s, Script 2.35 s; 20 long tasks, the longest 2,688 ms attributed to `main.js`. Forced-reflow insight points at ScrollTrigger's `refresh()` (`getBoundingClientRect` per trigger) — there are ~130 triggers on the home page (68 `[data-split]`, 44 `[data-reveal]`, carousels, pins). DOM is 2,573 elements, 1,144 of which are `span.char`.
- **Files:** `src/js/animations.js` `splitText()`/`splitHeadline()` (chars for every `h1, h2, h3, [data-split]`), `replayable()`; `src/js/main.js` init order.
- **Fix (in order of payoff, no visual change intended):**
  1. Split into **words** by default and chars only for the hero + section display lines (`data-split="chars"`). ≈1,144 → ≈250 animated nodes, one ScrollTrigger each stays.
  2. Do not hide the hero headline behind JS: render it visible in CSS and run the split/reveal as an *enhancement* after `requestIdleCallback`/first paint, so the browser paints the LCP text from HTML. Alternatively keep the entrance but gate `immediateRender` to the hero only.
  3. Batch ScrollTriggers: one `ScrollTrigger.batch()` per section for reveals instead of one trigger per element, and set `ScrollTrigger.config({ limitCallbacks: true, ignoreMobileResize: true })`.
  4. Code-split: `lenis`, the cursor engine and carousels behind `matchMedia('(pointer:fine)')`/interaction; keep `main.js` under ~40 kB gz for the first paint path.
- **Verification limit:** lab only; expect LCP → ≈2.5–3 s on this profile, but confirm with a re-run under identical settings.

### H-2 · Home page loads ~45 MB: 12 autoplaying 720p videos start downloading at once
- **Category:** Performance (bandwidth, memory, INP), also the reason desktop Lighthouse OOMs here.
- **Evidence:** `total-byte-weight` 45,797 KiB; top six requests are Mixkit MP4s (6.1, 4.8, 4.6, 3.9, 3.6, 3.3 MB). Markup has `preload="metadata"` on all 13 `<video>`s but `autoplay` on 12 forces full fetch as soon as they are in the DOM, regardless of viewport.
- **Files:** `index.html` featured cards, ride band, collage, story inset; `src/js/chrome.js` / section scripts.
- **Fix:** keep only the hero video autoplaying; every other video gets `preload="none"`, a `poster`, and `data-src` swapped in + `.play()` from an IntersectionObserver (pause + `removeAttribute('src')`/`load()` on exit). Respect `prefers-reduced-data` and `navigator.connection.saveData` by leaving the poster. Expected first-load payload drops from ~45 MB to under 5 MB.

### H-3 · CLS 0.142 on product and about (threshold 0.1)
- **Category:** Performance (CLS)
- **Evidence:** product: culprit `.pdp__info`, cause = three Fontshare woff2 swaps (General Sans, Cabinet Grotesk, Clash Display) arriving after first paint with `font-display: swap`. About: culprit `section.statement` shifting ~240 px below the split `h1` (word spans re-wrap once JS splits the headline); no font cause listed.
- **Fix:** (a) add metric-matched fallbacks: `@font-face { font-family: "Clash Display Fallback"; src: local("Arial Bold"); size-adjust/ascent-override/descent-override }` for the three families and put them in the stacks (metrics can be computed from the TTFs already in `scripts/fonts/`); (b) self-host the woff2 subsets and `<link rel="preload" as="font">` the two above-the-fold weights, which also removes the render-blocking Fontshare CSS (see M-1); (c) make `.word { display:inline-block }` not change wrapping: split by words *preserving* the original whitespace text nodes and give `.word` `white-space: nowrap` only.

## Medium priority (5)

- **M-1 · Render-blocking font CSS** (est. 760 ms of a 1,680 ms chain): `https://api.fontshare.com/v2/css?...` is a blocking stylesheet from a third origin. Self-host the fonts (Fontshare licence allows it) or load the CSS with `media="print" onload="this.media='all'"` plus the metric fallbacks from H-3. File: every `<head>`.
- **M-2 · No `srcset`**: `uses-responsive-images` est. 722 KiB (home), 612 KiB (product), 224 KiB (shop). 62 `<img>`, 0 `srcset`. Journal, ride band, finder and PDP hero images ship 1,400–1,900 px wide to a 412 px viewport. Generate 480/768/1200 variants (sharp, at build) and add `sizes`. Files: `index.html`, `pages/product.html`, `pages/shop.html`.
- **M-3 · Image encoding**: `image-delivery-insight` est. 185 KiB — `bike-delivery.webp`, `accessory-helmet.webp`, `accessory-battery.webp` can be re-encoded ~50 % smaller (quality 75–80, or AVIF with WebP fallback).
- **M-4 · Offscreen story images** (`.story-photo`, `.storycarousel img`, ~193 KiB) load eagerly; add `loading="lazy"` / `decoding="async"` (they are far below the fold; the carousel already swaps them).
- **M-5 · Unused code in the first-paint bundle**: ~30 KiB unused JS and ~11 KiB unused CSS on home. Falls out of the H-1 split; also consider per-page CSS entries so PDP/dashboard rules don't ship on the home page (188 kB CSS total, 33.7 kB gz).

## Low priority (3)

- **L-1 · Third-party cache headers**: six Fontshare woff2 files have short TTLs (`uses-long-cache-ttl`). Only fixable by self-hosting (M-1).
- **L-2 · DOM size 2,573 elements** on home (>1,500 warning). Mostly `span.char`; resolved by H-1 step 1.
- **L-3 · Auto-advancing content without controls** (About journey carousel, hero widget): passes automated checks but is a WCAG 2.2.2 judgement call. Both pause on hover/focus and honour reduced motion; if a user-visible pause is wanted, add a single "Pause" toggle to the journey band. (Product decision: user explicitly asked for no controls.)

## Summary

- **Performance:** measured on 8 pages; 3 pages below 70 (home, shop, product). Root causes are concentrated and structural: split-text + per-element ScrollTriggers (H-1), eager autoplay video (H-2), font-swap and split-induced shifts (H-3), no responsive images (M-2). Contact/faq/login/404 are 95–96.
- **Accessibility:** automated 100 on all 8 pages after fixes (was 91 on product). 10 manual checks per page remain (focus order, screen-reader labelling, keyboard traps in the mega menu/search overlay, custom cursor never hides focus rings).
- **SEO:** 100 on indexable pages; JSON-LD present (Organization, WebSite, ItemList, Product, FAQPage, LocalBusiness); 404/login correctly `noindex`. Sitemap + robots still placeholders for the real domain.
- **Best practices:** 100 after favicon fix. CSP/HSTS/frame-ancestors via hosting headers; no deprecated APIs.
- **Agentic browsing:** not available in Lighthouse 12.8 CLI. Source review: all forms have labels, controls have names/roles, no WebMCP, no `llms.txt` (optional).
